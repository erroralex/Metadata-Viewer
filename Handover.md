- Repo hygiene pass:
  - Added `LICENSE.md` (MIT + Commons Clause, matching Latent Library's license — free to use/modify/distribute, but the Software itself can't be sold/resold as a hosted or paid service).
  - Added `CONTRIBUTING.md` covering local dev setup (`mvn clean package` / `mvn test`), pointing at `AGENTS.md` for the full engineering rulebook.
  - Added `.github/workflows/build.yml`: on `windows-latest`/`ubuntu-latest`/`macos-latest` whenever a `v*` tag is pushed. Builds the shaded jar per-OS (each resolves its own `javafx.platform` via the existing pom.xml profiles), then packages it into a standalone native app via `jpackage --type app-image` — no Java required to run the release download. The bundled runtime's module list is computed per-build via `jdeps --print-module-deps` against the shaded jar rather than hardcoding the `java.se` umbrella module (which is most of the JDK); `--jlink-options "--strip-debug --no-header-files --no-man-pages --compress=2"` trims it further. Each app-image is zipped (`MetadataViewer-windows.zip`/`-linux.zip`/`-macos.zip`) and attached to the GitHub Release via `softprops/action-gh-release`. Windows/Linux icons come from the existing `src/main/resources/icon.ico`/`icon.png`; macOS has no `.icns` yet, so it ships with jpackage's default icon.

  - User feedback (from a downloaded Windows zip): running the `.exe` from inside Explorer's zip-browsing view (rather than a real "Extract All") silently fails and looks like it needs extracting twice — Explorer copies out just the one file, without its required sibling `app`/`runtime` folders. Also asked why those sibling folders exist at all when a single portable `.exe` was expected.
  - Added a "Pack into single-file exe (Warp)" step to `build.yml`, **Windows-only**: after `jpackage` produces the `dist/MetadataViewer/` app-image folder, [Warp](https://github.com/dgiagio/warp) (`windows-x64.warp-packer.exe` from its v0.3.0 release) wraps that whole folder into one genuinely standalone `MetadataViewer-windows.exe` — it self-extracts to a temp dir at launch and runs from there, so there's truly only one file to download and run. The zip step is now skipped for Windows (`if: runner.os != 'Windows'`); Linux/macOS keep the zipped app-image folder as before, since Warp's non-Windows runner stubs are far less maintained and this specific problem was Windows-only (reported via Explorer's zip-view behavior). README's Getting Started section now gives OS-specific instructions (run the `.exe` directly on Windows; extract-then-run the `.zip` on macOS/Linux).
